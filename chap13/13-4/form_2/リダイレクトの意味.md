PHPの入門書に以下のようなコードがあります。

util.php
```
function cken(array $data): bool {
  return mb_check_encoding($data);
}
```

search.php
```
require_once('util.php');
$gobackURL = 'searchForm.html';

if (!cken($_POST)) {

}
```

この場合の `header("Location:{$gobackURL}")` というのは、
ブラウザに対するレスポンスだと考えていいでしょうか？
もし、不正な文字エンコードに攻撃があったとしても、
相手がブラウザ以外から攻撃してきたのなら、このリダイレクトの処理は

---

はい、その理解でほぼ正しいです。

ただし、**`header("Location:...")` はブラウザ専用の処理ではなく、HTTPレスポンスのヘッダーを送信する処理**です。この点を押さえておくと、ブラウザ以外からの攻撃についても理解しやすくなります。

順番に説明します。

## 1. `header("Location:...")` は何をしているのか

今回のコードを見てみましょう。

```php
require_once('util.php');
$gobackURL = 'searchForm.html';

if (!cken($_POST)) {
  header("Location:{$gobackURL}");
  exit();
}
```

`cken($_POST)` が `false` を返した場合、次の2つの処理が実行されます。

**① `header("Location:{$gobackURL}")`**

Webサーバーからクライアントに送信するHTTPレスポンスに、リダイレクトを指示する `Location` ヘッダーを設定します。

例えば、レスポンスは概念的には次のようになります。

```http
HTTP/1.1 302 Found
Location: searchForm.html
```

ここで、HTTPステータスコードの `302 Found` は、別のURLに一時的に移動するよう指示するものです。

なお、実際のステータスコードはPHPの設定や、それ以前の処理によって異なる場合があります。

**② `exit()`**

PHPのスクリプトの実行を終了します。

したがって、この後にPHPの処理が記述されていても、実行されません。

---

## 2. ブラウザ以外から攻撃された場合はどうなるのか

ここが、ご質問の重要なポイントです。

例えば、攻撃者がブラウザではなく、`curl` コマンドを使ってリクエストを送信したとします。

```bash
curl -X POST \
  -d 'name=test' \
  http://localhost/search.php
```

この場合も、PHP側では通常のHTTPリクエストとして処理されます。

`$_POST` に格納されたデータに対して `cken()` が実行され、文字エンコーディングの検査結果が `false` であれば、次の処理が実行されます。

```php
header("Location:{$gobackURL}");
exit();
```

このとき、ブラウザからアクセスされた場合と同じように、HTTPレスポンスにリダイレクトの指示が設定されます。

ただし、**その指示に従って実際にリダイレクトするかどうかは、リクエストを送信したクライアント側の動作によります。**

例えば、次のような違いがあります。

| クライアント | `Location` ヘッダーを受け取った場合 |
|---|---|
| 通常のブラウザ | 通常はリダイレクト先に移動する |
| `curl` | 通常は自動的にリダイレクトしない |
| `curl -L` | リダイレクトを追跡する |
| 独自に作成したプログラム | プログラムの実装次第 |

つまり、ブラウザ以外のクライアントでは、リダイレクトの指示を無視することもできます。

しかし、それによってPHP側の `exit()` が無効になるわけではありません。

---

## 3. `exit()` があれば、問題ないのでしょうか？

ご質問の理解は、重要な部分で正しいです。

仮に、攻撃者が不正な文字エンコーディングのデータを送信し、リダイレクトの指示を無視したとしても、次のコードが実行されます。

```php
if (!cken($_POST)) {
  header("Location:{$gobackURL}");
  exit();
}

// この位置に後続の処理があっても、
// cken($_POST) が false なら実行されない。
```

`exit()` は、クライアントがブラウザかどうかに関係なく、PHPスクリプトの実行を終了します。

したがって、**リダイレクトが実行されるかどうかと、不正なデータに対する後続処理を防止できるかどうかは、別の問題**です。

今回のコードでは、`cken($_POST)` が `false` なら、その後のPHPの処理に進まないという点が重要です。

### ただし、1点だけ注意が必要です

`exit()` は、PHPのスクリプトを終了させるだけです。

例えば、次のような場合まで自動的に防いでくれるわけではありません。

- `cken()` の検査だけでは検出できない不正なデータが送信された場合
- それ以前の処理ですでに問題が発生していた場合
- 別のPHPスクリプトに、同様の検査を通さずに処理する経路がある場合

また、`mb_check_encoding()` は指定されたデータが特定の文字エンコーディングとして妥当かどうかを検査する関数です。**文字エンコーディングが正しいことと、そのデータが安全であることは同じではありません。**

---

## 4. 今回のコードで、もう1つ確認しておきたいこと

提示された `util.php` には、次の関数が定義されています。

```php
function cken(array $data): bool {
  return mb_check_encoding($data);
}
```

ここで、`mb_check_encoding()` に文字エンコーディングの指定がありません。

PHPの `mb_check_encoding()` は、第2引数を省略すると、現在の内部文字エンコーディングを使用します。

そのため、このコードでは、例えば次のように書く場合とは指定方法が異なります。

```php
function cken(array $data): bool {
  return mb_check_encoding($data, 'UTF-8');
}
```

後者では、UTF-8として妥当なデータかどうかを明示的に検査します。

ただし、実際にどちらを使用すべきかは、アプリケーションが想定する文字エンコーディングや、PHPの設定によって決まります。

---

## まとめ

ご質問のポイントを整理します。

1. **`header("Location:...")` は、HTTPレスポンスのヘッダーを設定する処理です。** ブラウザ専用ではありません。
2. **ブラウザ以外のクライアントは、リダイレクトの指示を無視できます。** 例えば、`curl` は通常、`Location` ヘッダーを受け取っただけでは自動的にリダイレクトしません。
3. **`exit()` は、クライアントの種類に関係なくPHPスクリプトの実行を終了します。** そのため、リダイレクトが実行されなくても、後続のPHP処理には進みません。
4. ただし、`exit()` が保証するのはスクリプトの終了であり、不正なデータをすべて検出できることではありません。

したがって、今回のコードについては、**リダイレクトそのものをセキュリティ対策と考えるのではなく、検査に失敗した場合に `exit()` で後続処理を止めることが重要**、と理解するとよいでしょう。
