PHPの入門書に、以下のコードが紹介されています。

```
<?php
$ninzu = "3人" + "2人";
$price = "500円" * $ninzu;
$price = $price * "0.85 割引率";
echo "人数 {$ninzu}人、 料金 {$price}円";
?>
```

また、次のコードも紹介されています。

```
<?php
# error_reporting(0);  # エラーを非表示にする場合はコメントアウトを外す
$a = 2 + "15";
$b = 2.3 + "1.25";
$c = 2 + "-4";
$d = " 5 " + " 6 ";
$e = "5 6" + 7;
$f = "1.2e-3" * 2;  # 1.2 * 10^-3 = 1.2 * 1/1000 = 0.0012
$g = "250 円" * 2;
# $h = "番号 99" + 1;
$h = 0;
# $i = 10 + "円";
$i = 1;

echo "a {$a}、 b {$b}、 c {$c}、 d {$d}、 e {$e}、 f {$f}、 g {$g}、 h {$h}、 i {$i} ";
```

これらは、phpの特徴として紹介されているのですが、
この特徴に対してプログラマはどう対処すべきでしょうか？
積極的に利用すべきでしょうか？
あるいは、できるだけ利用しないようにすべきでしょうか？

僕は、このような特徴は、できるだけ利用しないようにすべきだと思うのですが、
どうでしょうか？

---


僕も、基本的には **このような暗黙的な型変換を積極的に利用するのではなく、できるだけ避けるべきだ** という考えに賛成です。

ただし、PHPの型変換をすべて避ける必要があるわけではありません。大切なのは、**どのような型変換が行われるのかを理解したうえで、意図した型変換と、PHP任せの型変換を区別すること** だと思います。

入門書で紹介されているコードを題材に、プログラマとしてどう考えるべきか整理してみましょう。

## 1. 入門書のコードは何を示しているのか

最初のコードを見てみます。

```php
<?php
$ninzu = "3人" + "2人";
$price = "500円" * $ninzu;
$price = $price * "0.85 割引率";
echo "人数 {$ninzu}人、 料金 {$price}円";
?>
```

このコードは、文字列として定義された値を算術演算子で計算しようとしています。

たとえば、次の式です。

```php
$ninzu = "3人" + "2人";
```

人間が読むと、3人と2人を足して5人にするつもりだと考えられます。

しかし、PHPにとって `"3人"` や `"2人"` は文字列です。

PHPでは、算術演算子を使うときに、文字列を数値として扱えるかどうかに応じて型変換が行われます。

ただし、ここで重要なのは、**PHPのバージョンや変換対象の文字列によって、結果やエラーの扱いが異なる** という点です。

たとえば、数値の後ろに文字が続く文字列は、現在のPHPでは、単純に先頭の数値だけを取り出して計算するとは限りません。

PHP 8系では、数値として解釈できる文字列と、数値として解釈できない文字列、数値の後ろに余分な文字がある文字列などを区別して扱います。

そのため、このコードを「PHPは文字列から数値部分を取り出して計算してくれる」と理解するのは危険です。

また、次のコードにも注意が必要です。

```php
$price = $price * "0.85 割引率";
```

意図としては、料金に0.85を掛けて15％割引にしたいのでしょう。

しかし、割引率を表す文字列の中に説明用の文字まで含めています。計算に使う値と、人間が読むための説明が混在しているため、プログラムとしては好ましくありません。

数値は数値として扱い、説明は別の場所に記述するのが基本です。

## 2. PHP 8では、どのような問題が起こるのか

2番目のコードを見てみましょう。

```php
$a = 2 + "15";
$b = 2.3 + "1.25";
$c = 2 + "-4";
$d = " 5 " + " 6 ";
$e = "5 6" + 7;
$f = "1.2e-3" * 2;
$g = "250 円" * 2;
```

これらは、PHPの型変換の特徴を理解するための例としては意味があります。

ただし、**すべての例を同じ種類の型変換として理解しないことが重要です。**

| 式 | 結果 | 解説 |
|---|---:|---|
| `2 + "15"` | `17` | 数値として解釈できる文字列 |
| `2.3 + "1.25"` | `3.55` | 数値として解釈できる文字列 |
| `2 + "-4"` | `-2` | 負の数を表す数値文字列 |
| `" 5 " + " 6 "` | `11` | 前後の空白を含む数値文字列 |
| `"5 6" + 7` | `12` | 数値の後ろに余分な文字があるため、警告が発生する |
| `"1.2e-3" * 2` | `0.0024` | 指数表記を使った数値文字列 |
| `"250 円" * 2` | `500` | 数値の後ろに余分な文字があるため、警告が発生する |

※ 上表はPHP 8系における通常の算術演算を前提としています。数値の後ろに余分な文字がある文字列については、PHP 8では警告が発生します。数値として解釈できない文字列は、`TypeError` になる場合があります。

たとえば、次のコードです。

```php
$price = "500円" * 2;
```

PHP 8系では、数値部分を利用して計算できる場合がありますが、警告が発生します。

一方、次のコードはどうでしょうか。

```php
$price = "円" * 2;
```

こちらは数値として解釈できる部分がないため、PHP 8系では `TypeError` になります。

この違いを理解することは大切です。

また、次のようなコードもあります。

```php
$f = "1.2e-3" * 2;
```

これは問題ありません。

`"1.2e-3"` は、単に数値を文字列で表現したものだからです。

`1.2e-3` は `0.0012` を意味する正当な数値表記です。

したがって、**数値を表す文字列を数値として扱うことと、数値以外の文字を含む文字列を数値として扱うことは、区別して考える必要があります。**

---

## 3. プログラマはどう対処すべきか

僕なら、次の3つに分けて考えます。

### ① 数値を扱う変数には、最初から数値を代入する

たとえば、次のコードです。

```php
$ninzu = 3 + 2;
$price = 500 * $ninzu;
$price = $price * 0.85;

echo "人数 {$ninzu}人、料金 {$price}円";
```

これなら、人数や料金の計算に文字列を使う必要がありません。

実行結果は次のようになります。

```text
人数 5人、料金 2125円
```

数値として扱うべきものは数値で保持し、表示するときに必要な文字列を付け加えます。

このようにすれば、コードを読んだ人も、変数がどのような値を保持しているのか理解しやすくなります。

### ② 文字列から数値を取り出す必要があるなら、明示的に変換する

たとえば、フォームから次のような文字列を受け取ったとします。

```php
$price = "500";
```

この文字列を数値として扱いたいのであれば、状況に応じて明示的に変換できます。

```php
$price = (int) $price;
```

ただし、ここで注意したいことがあります。

**型変換を明示することと、入力値が正しいことを確認することは別です。**

たとえば、ユーザーが入力した値が `"500円"` だったとしても、単純に `(int)` を指定すれば、入力が正しいと保証されるわけではありません。

ユーザー入力を扱う場合は、まず入力形式が正しいかを検証し、そのうえで数値として扱う必要があります。

### ③ 数値として解釈できない文字列を、計算に利用しない

たとえば、次のコードです。

```php
$price = "500円";
```

この変数を料金の計算に利用するのは避けたほうがよいでしょう。

代わりに、次のようにします。

```php
$price = 500;
$unit = "円";
```

そして、表示するときに組み合わせます。

```php
echo "{$price}{$unit}";
```

これなら、計算と表示の役割が明確になります。

もちろん、実際のプログラムでは、料金を整数で管理するか、浮動小数点数で管理するかなど、別の設計上の問題もあります。しかし、少なくとも数値と単位を分けるという考え方は重要です。

## 4. では、PHPの暗黙的な型変換は利用しないほうがよいのか

ここは少し補足したいところです。

PHPでは、型宣言をしていない変数に異なる型の値を代入できます。

```php
$value = 100;
$value = "100";
```

このようなこと自体はPHPの特徴であり、必ずしも悪いことではありません。

また、数値を表す文字列を計算に使えることも、PHPの言語仕様の一部です。

しかし、これらの特徴があるからといって、**意図的に型変換を曖昧にする書き方を推奨する理由にはなりません。**

特に、次のようなコードは避けるべきです。

```php
$price = "500円" * 2;
```

その理由は、次のとおりです。

- コードを読んだ人が、意図した計算なのか判断しにくい。
- 警告やエラーの原因になり得る。
- PHPのバージョンによる挙動の違いを考慮する必要がある。
- 入力値の不備を見逃す原因になり得る。

一方、次のようなコードは問題ありません。

```php
$price = 500 * 2;
```

また、次のコードも、文字列が正当な数値表現であることが分かっているなら、PHPの仕様に沿った書き方です。

```php
$price = "500" * 2;
```

ただし、数値を保持する変数にわざわざ文字列を代入する必要がないなら、最初から数値を使うほうが、コードの意図が明確になります。

## 5. 入門書では、この特徴をどう教えるべきか

ここは、プログラミングを教える立場からも重要なポイントだと思います。

入門書で型変換を紹介すること自体には意味があります。

PHPがどのように値を扱うのかを理解していれば、既存のコードを読んだり、警告やエラーの原因を調べたりするときに役立ちます。

ただし、学習者が次のように理解してしまうのは避けたいところです。

> PHPは文字列の中から数値を取り出して計算してくれるので、数値と文字列を区別しなくてもよい。

これは適切な理解ではありません。

むしろ、次のように教えるのがよいと思います。

1. PHPには、数値を表す文字列を数値として扱える仕組みがある。
2. ただし、文字列の内容によっては警告やエラーが発生する。
3. 暗黙的な型変換の挙動を知っておくことは、コードの理解やデバッグに役立つ。
4. **実際のプログラムでは、データの意味に合った型を使い、意図しない暗黙的な型変換を避ける。**

つまり、言語仕様として知っておくことと、日常的なプログラミングで積極的に使うことは、別の話なのです。

## まとめ

ご自身の考えは、実務的なプログラミングの方針として妥当だと思います。

私なら、次のように整理します。

| 項目 | 方針 |
|---|---|
| 数値を表す文字列を計算に使える仕組み | 仕様として理解しておく |
| 数値を扱う変数に数値を代入する | 基本とする |
| 数値と単位を同じ文字列に含める | 計算用のデータでは避ける |
| ユーザー入力を暗黙的に数値変換する | 避け、入力値を検証する |
| 明示的な型変換 | 必要性を確認したうえで利用する |
| 意図しない暗黙的な型変換 | できるだけ避ける |

**「PHPにはこのような型変換の仕組みがある」と知っておくことは重要ですが、「この仕組みを積極的に利用してプログラムを書く」必要はありません。**

特に入門者には、型変換の仕組みを知識として学びつつ、普段のコードでは、数値は数値、文字列は文字列として明確に扱う習慣を身につけてもらうのがよいと思います。
